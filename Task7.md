# Лабораторная работа: распределение файлов по нескольким носителям

# Вариант 7

## Общая идея

Разработать консольное приложение для переноса большого набора файлов с помощью нескольких носителей ограниченного объёма.

Пользователь выбирает:

* исходные файлы и каталоги;
* носители, которые будут использоваться;
* порядок заполнения носителей.

Программа должна объединить выбранные данные в единый переносимый набор, разделить его на части подходящего размера и последовательно разместить эти части на носителях.

На первом носителе создаётся манифест. Он описывает состав переносимого набора, порядок частей, распределение частей по носителям и сведения, необходимые для восстановления исходных файлов.

На другом компьютере программа должна прочитать манифест, поочерёдно запросить необходимые носители, проверить целостность частей и восстановить исходную структуру файлов.

Практический сценарий: пользователю необходимо перенести объём данных, который не помещается на одну флешку, карту памяти, оптический диск или другой доступный носитель.

---

# 1. Работа с приложением

Приложение должно управляться через текстовые команды или меню.

Пользователь должен иметь возможность:

* создать новый переносимый набор;
* выбрать файлы и каталоги;
* просмотреть состав выбранных данных;
* добавить носители и задать порядок их использования;
* построить план распределения без записи данных;
* начать запись;
* проверить записанный набор;
* продолжить прерванную запись;
* восстановить исходные файлы;
* просмотреть информацию из манифеста;
* перезагрузить конфигурацию;
* завершить работу.

Пример командного интерфейса:

```text
> create-set vacation-archive
> add-file photos.zip
> add-directory documents
> sources
> add-media E:\
> add-media F:\
> media
> plan
> write
> verify
> restore D:\Restored
> manifest
> reload
> exit
```

Разрешается реализовать нумерованное меню.

Типичный сценарий переноса:

1. Пользователь создаёт новый набор.
2. Выбирает исходные файлы и каталоги.
3. Подключает первый носитель.
4. Программа определяет доступное пространство.
5. Пользователь добавляет остальные носители в необходимом порядке.
6. Программа строит план распределения.
7. Пользователь подтверждает план.
8. Программа последовательно заполняет носители.
9. После записи каждого носителя выполняется проверка.
10. На первом носителе сохраняется итоговый манифест.
11. На другом компьютере пользователь запускает восстановление.
12. Программа запрашивает носители в порядке, указанном в манифесте.
13. После проверки всех частей восстанавливаются исходные файлы.

---

# 2. Формирование переносимого набора

Пользователь должен иметь возможность добавить:

* отдельный файл;
* несколько файлов;
* каталог;
* каталог вместе со всеми вложенными файлами.

Для каждого добавленного объекта программа должна определить:

* исходный путь;
* относительный путь внутри переносимого набора;
* размер;
* дату изменения;
* доступность для чтения.

При добавлении каталога его внутренняя структура должна сохраняться.

Например:

```text
Исходные данные:

C:\Transfer\Documents\report.docx
C:\Transfer\Documents\Tables\budget.xlsx
C:\Transfer\Photos\photo01.jpg
```

После восстановления:

```text
<каталог восстановления>\Documents\report.docx
<каталог восстановления>\Documents\Tables\budget.xlsx
<каталог восстановления>\Photos\photo01.jpg
```

Программа должна обнаруживать конфликты относительных путей.

Например, нельзя добавить два разных файла, если оба должны быть восстановлены под именем:

```text
Documents\report.docx
```

Перед построением плана программа должна показать сводку:

```text
Набор: vacation-archive

Файлов: 2 418
Каталогов: 126
Общий объём: 31,7 ГБ

Недоступно для чтения: 2 файла
Конфликтов путей: 0
```

При наличии недоступных файлов пользователь должен выбрать:

* исключить их из набора;
* повторить проверку;
* отменить формирование набора.

---

# 3. Выбор и порядок носителей

Носитель в рамках задания представляет собой выбранный пользователем каталог, расположенный на флешке, карте памяти, внешнем диске или другом устройстве хранения.

Для каждого носителя программа должна определить:

* путь;
* доступный объём;
* общий объём;
* метку или указанное пользователем название;
* порядковый номер;
* возможность записи;
* объём, который разрешено занять.

Пользователь должен самостоятельно задать порядок заполнения носителей.

Пример:

```text
Носители:

1. BLUE-USB
   Путь: E:\
   Доступно: 14,6 ГБ

2. OLD-FLASH
   Путь: F:\
   Доступно: 7,2 ГБ

3. BACKUP-SD
   Путь: G:\
   Доступно: 28,9 ГБ
```

Порядок должен влиять на распределение частей. Сначала программа заполняет первый носитель, затем второй и далее.

Пользователь должен иметь возможность:

* добавить носитель;
* удалить носитель из списка;
* изменить его позицию;
* повторно определить доступный объём;
* ограничить используемый объём вручную.

Программа не должна считать всё свободное пространство доступным автоматически. На каждом носителе необходимо оставить резерв, заданный в конфигурации.

Например:

```text
Доступно физически: 14,6 ГБ
Резерв: 500 МБ
Разрешено использовать: 14,1 ГБ
```

---

# 4. Планирование распределения

До начала записи программа должна построить полный план.

План должен содержать:

* общее количество частей;
* размер каждой части;
* носитель для каждой части;
* ожидаемый объём данных на каждом носителе;
* оставшееся свободное пространство;
* предупреждения;
* информацию о том, хватает ли суммарного объёма.

Пример:

```text
План набора vacation-archive

Исходный объём: 31,7 ГБ
Носителей: 3
Частей: 9

Носитель 1: BLUE-USB
Части: 1–4
Будет записано: 13,8 ГБ
Останется: 0,8 ГБ

Носитель 2: OLD-FLASH
Части: 5–6
Будет записано: 6,9 ГБ
Останется: 0,3 ГБ

Носитель 3: BACKUP-SD
Части: 7–9
Будет записано: 11,0 ГБ
Останется: 17,9 ГБ
```

Размер одной части ограничивается настройкой конфигурации.

При определении размера части необходимо учитывать:

* максимальный размер части из конфигурации;
* доступный объём носителя;
* резерв свободного пространства;
* ограничения файловой системы носителя;
* место, необходимое для манифеста и служебных данных.

Если некоторый носитель не способен вместить даже одну часть, программа должна сообщить об этом до начала записи.

Если суммарного объёма недостаточно, запись не начинается.

Пример:

```text
Недостаточно места для создания набора.

Требуется: 31,7 ГБ
Доступно с учётом резерва: 28,4 ГБ
Не хватает: 3,3 ГБ

Добавьте ещё один носитель
или измените состав исходных данных.
```

После построения плана пользователь должен подтвердить начало записи.

---

# 5. Создание и размещение частей

Программа должна сформировать последовательность пронумерованных частей.

Пример имён:

```text
vacation-archive.part001
vacation-archive.part002
vacation-archive.part003
```

Часть может содержать:

* один полный исходный файл;
* несколько небольших файлов;
* фрагмент крупного файла;
* служебные данные, необходимые для восстановления.

Пользователь не должен вручную определять, какие файлы попадут на конкретный носитель. Распределение выполняется программой согласно построенному плану.

Каждый носитель должен содержать служебное описание, позволяющее определить:

* идентификатор переносимого набора;
* номер носителя;
* общее количество носителей;
* какие части расположены на этом носителе;
* завершена ли запись носителя;
* соответствует ли носитель выбранному набору.

Пример:

```text
Набор: vacation-archive
Идентификатор: 8f31c2
Носитель: 2 из 3
Части: 5, 6
Состояние: запись завершена
```

Это описание не заменяет основной манифест, но позволяет обнаружить перепутанный носитель.

После записи части программа должна проверить:

* существует ли созданный файл;
* совпадает ли его размер с ожидаемым;
* совпадает ли контрольная сумма;
* полностью ли завершена запись.

Носитель считается готовым только после успешной проверки всех размещённых на нём частей.

---

# 6. Последовательная работа с носителями

Программа не должна требовать одновременного подключения всех носителей.

После завершения записи текущего носителя она должна вывести сообщение:

```text
Носитель 1 из 3 успешно записан и проверен.

Можно безопасно отключить:
BLUE-USB

Подключите следующий носитель:
OLD-FLASH
```

После подключения следующего носителя программа должна проверить, что выбран именно ожидаемый носитель.

Необходимо обнаруживать следующие ситуации:

* подключён уже заполненный носитель;
* подключён носитель из другого набора;
* носитель имеет меньший доступный объём, чем при планировании;
* носитель защищён от записи;
* пользователь выбрал неправильный каталог;
* содержимое носителя изменилось после планирования.

Если доступного места стало меньше, программа должна попытаться перестроить оставшуюся часть плана.

Уже успешно записанные носители при этом не должны изменяться.

Если перестроить план невозможно, операция приостанавливается до добавления нового носителя или освобождения места.

---

# 7. Манифест переносимого набора

Основной манифест должен сохраняться на первом носителе.

Он должен содержать:

* имя и уникальный идентификатор набора;
* дату создания;
* список исходных файлов;
* относительные пути;
* размеры исходных файлов;
* контрольные суммы исходных файлов;
* список частей;
* размеры и контрольные суммы частей;a
* порядок частей;
* распределение частей по носителям;
* порядок носителей;
* настройки, существенные для восстановления;
* сведения о завершённости операции.

Пример представления:

```json
{
  "setId": "8f31c2",
  "name": "vacation-archive",
  "createdAt": "2026-10-14T18:30:00",
  "mediaCount": 3,
  "parts": [
    {
      "number": 1,
      "fileName": "vacation-archive.part001",
      "mediaNumber": 1,
      "size": 3758096384,
      "checksum": "..."
    },
    {
      "number": 2,
      "fileName": "vacation-archive.part002",
      "mediaNumber": 1,
      "size": 3758096384,
      "checksum": "..."
    }
  ]
}
```

Формат манифеста выбирается разработчиком.

Манифест должен сохраняться таким образом, чтобы незавершённый набор нельзя было принять за полностью готовый.

После успешной записи последнего носителя программа должна обновить манифест и отметить набор как завершённый.

Если первый носитель недоступен на завершающем этапе, итоговый манифест должен быть сохранён во временном каталоге программы. Пользователь должен получить предупреждение о необходимости повторно подключить первый носитель и завершить операцию.

---

# 8. Продолжение прерванной записи

Состояние создания набора должно сохраняться между запусками программы.

Если работа была прервана, приложение должно определить:

* какие части уже созданы;
* какие части успешно проверены;
* какие носители завершены;
* какая часть записывалась в момент прерывания;
* с какого места можно продолжить.

Пример:

```text
Обнаружена незавершённая операция:

Набор: vacation-archive
Завершено носителей: 1 из 3
Последняя проверенная часть: 4
Следующая часть: 5

Продолжить запись?
```

Часть, запись которой не была завершена или проверена, должна быть создана заново.

Уже проверенные части не должны перезаписываться без необходимости.

Если исходные файлы изменились после построения плана, программа должна предупредить пользователя.

В таком случае пользователь может:

* отменить продолжение;
* заново сформировать весь набор;
* исключить изменившиеся файлы и перестроить оставшийся план.

Нельзя продолжать операцию так, чтобы восстановленный набор незаметно содержал смесь старых и новых версий исходных данных.

---

# 9. Проверка готового набора

Пользователь должен иметь возможность проверить ранее созданный набор без его восстановления.

Проверка выполняется по манифесту.

Программа должна последовательно запросить носители и проверить:

* принадлежность носителя выбранному набору;
* номер носителя;
* наличие всех ожидаемых частей;
* размеры частей;
* контрольные суммы;
* отсутствие лишних частей с тем же идентификатором;
* завершённость набора.

Пример результата:

```text
Проверка набора vacation-archive

Носитель 1: успешно
Носитель 2: успешно
Носитель 3: ошибка

Повреждена часть:
vacation-archive.part008

Ожидаемая контрольная сумма:
4D7A...

Фактическая контрольная сумма:
A193...

Восстановление полного набора невозможно.
```

Если повреждена часть, программа должна указать:

* её номер;
* носитель;
* ожидаемый размер;
* фактический размер;
* ожидаемую контрольную сумму;
* фактическую контрольную сумму, если она была вычислена.

---

# 10. Восстановление исходных файлов

Для восстановления пользователь выбирает:

* манифест;
* выходной каталог.

Программа должна проверить, что набор завершён, и показать сводку:

```text
Набор: vacation-archive
Носителей: 3
Частей: 9
Исходных файлов: 2 418
Исходный объём: 31,7 ГБ
Каталог восстановления: D:\Restored
```

До начала восстановления программа должна проверить наличие достаточного свободного места.

Носители запрашиваются в порядке, указанном в манифесте.

Перед использованием каждой части должна проверяться её контрольная сумма.

После обработки всех частей программа должна восстановить:

* исходные имена файлов;
* относительные пути;
* содержимое файлов;
* пустые каталоги, если они были включены в набор.

После восстановления необходимо проверить контрольные суммы исходных файлов.

Если хотя бы один файл не прошёл проверку, операция должна считаться завершённой с ошибками.

Программа не должна удалять части с носителей после восстановления.

Если в выходном каталоге уже существует файл с таким же именем, поведение определяется конфигурацией:

* запретить перезапись;
* запросить подтверждение;
* создать файл с новым именем;
* перезаписать.

---

# 11. Необязательная промежуточная архивация

Перед разбиением данных программа может создать единый архив с помощью готовой утилиты или библиотеки.

Например, допускается использовать:

* `tar`;
* `zip`;
* `7z`;
* другую распространённую утилиту архивации.

В этом случае общий процесс выглядит так:

1. Выбранные файлы объединяются в архив.
2. Архив разделяется на части.
3. Части распределяются по носителям.
4. При восстановлении части объединяются.
5. Архив проверяется и распаковывается.

Использование архивации не является обязательным.

Если архивация применяется, программа должна:

* проверить наличие выбранной утилиты;
* показать, какой формат используется;
* сохранить эту информацию в манифесте;
* получить код завершения внешней команды;
* обнаружить ошибку создания или распаковки архива;
* удалить незавершённый промежуточный архив;
* не считать набор готовым до проверки архива.

Настройка уровня сжатия должна позволять отключить сжатие полностью. Это полезно для уже сжатых файлов: видео, изображений, архивов и установочных пакетов.

Использование внешнего архиватора не должно отменять проверку частей по контрольным суммам.

---

# 12. Конфигурационный файл

Настройки приложения должны храниться в отдельном конфигурационном файле.

Пример:

```json
{
  "workDirectory": "transfer-work",
  "logFile": "transfer-manager.log",
  "defaultPartSize": "2 GB",
  "minimumPartSize": "64 MB",
  "reservedSpacePerMedia": "500 MB",
  "verifyAfterWrite": true,
  "checksumAlgorithm": "SHA-256",
  "overwriteMode": "ask",
  "preserveEmptyDirectories": true,

  "archive": {
    "enabled": false,
    "command": "7z",
    "format": "7z",
    "compressionLevel": 0
  },

  "fileNameTemplate": "{setName}.part{number}",
  "mediaDescriptorFile": "media-info.json",
  "manifestFile": "manifest.json"
}
```

В конфигурации должны задаваться как минимум:

* рабочий каталог;
* путь к журналу;
* максимальный размер части;
* минимальный допустимый размер части;
* резерв свободного места на носителе;
* необходимость проверки после записи;
* способ поведения при существовании выходных файлов;
* параметры необязательной архивации;
* шаблон имён частей;
* имена служебных файлов.

Перед использованием конфигурация должна проверяться.

Например, минимальный размер части не может превышать максимальный, а резерв на носителе не может быть отрицательным.

---

# 13. Отчёты и журналирование

После создания набора программа должна сформировать итоговый отчёт.

Отчёт должен содержать:

* имя и идентификатор набора;
* список исходных объектов;
* общий объём;
* количество файлов;
* количество частей;
* список носителей;
* распределение частей;
* результаты проверки;
* предупреждения;
* ошибки;
* путь к манифесту;
* признак завершённости.

После восстановления отчёт должен содержать:

* имя набора;
* каталог восстановления;
* количество восстановленных файлов;
* количество проверенных файлов;
* количество повреждённых или пропущенных файлов;
* итоговый статус.

Приложение должно вести журнал работы.

В журнал необходимо записывать:

* запуск и завершение приложения;
* загрузку конфигурации;
* создание нового набора;
* добавление и исключение исходных файлов;
* добавление и изменение порядка носителей;
* построение и перестроение плана;
* начало и завершение записи каждого носителя;
* создание и проверку частей;
* прерывание и продолжение операции;
* создание и обновление манифеста;
* начало и завершение проверки;
* начало и завершение восстановления;
* ошибки чтения и записи;
* нехватку места;
* подключение неправильного носителя;
* ошибки внешней утилиты архивации;
* неизвестные команды;
* внутренние ошибки.

В журнале не требуется сохранять содержимое исходных файлов.

# 14. Проверка данных и обработка ошибок

Программа должна обнаруживать как минимум следующие проблемы:

* исходный файл не существует;
* файл недоступен для чтения;
* два объекта создают одинаковый относительный путь;
* носитель недоступен;
* носитель защищён от записи;
* на носителе недостаточно места;
* суммарного объёма носителей недостаточно;
* размер части превышает ограничение файловой системы;
* служебные файлы набора уже существуют;
* подключён носитель из другого набора;
* подключён носитель с неправильным номером;
* часть отсутствует;
* часть имеет неправильный размер;
* контрольная сумма не совпадает;
* манифест повреждён;
* набор не был завершён;
* исходные файлы изменились после планирования;
* недостаточно места для восстановления;
* выходной файл уже существует;
* запись была прервана;
* внешний архиватор отсутствует;
* архиватор завершился с ошибкой;
* промежуточный архив повреждён;
* конфигурация имеет неправильный формат.

Ошибка записи одной части не должна приводить к пометке всего носителя как успешно завершённого.

Если операция может быть продолжена, программа должна сохранить состояние и сообщить пользователю, что необходимо сделать.

Пример:

```text
Запись приостановлена.

Носитель: OLD-FLASH
Часть: 6 из 9
Причина: недостаточно свободного места.

Успешно записанные части сохранены.
Подключите дополнительный носитель
или освободите не менее 740 МБ.
```

# 15. Ограничения задания

В рамках лабораторной работы не требуется:

* работать с носителями на уровне физических секторов;
* самостоятельно создавать файловую систему;
* форматировать носители;
* изменять разделы диска;
* автоматически удалять существующие пользовательские файлы;
* восстанавливать повреждённые части;
* реализовывать алгоритм архивного сжатия;
* реализовывать криптографические хеш-функции;
* шифровать переносимый набор;
* работать с облачными хранилищами;
* передавать части по сети;
* создавать графический интерфейс.

Приложение должно работать только с явно выбранными пользователем файлами, каталогами и носителями.

Основная задача программы — спланировать распределение данных, надёжно разместить части на нескольких носителях и обеспечить последующую проверку и восстановление исходных файлов.
